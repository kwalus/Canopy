Common issue checklist
  • Reachable endpoint — If the peer is on a home network, port-forward {{ mesh_port }}. On a VPS or tunnel, make sure the advertised public endpoint is actually the one Canopy is sharing.
  • Firewall — Check that your OS firewall allows inbound connections on port {{ mesh_port }}.
  • Relay policy — Set to —. Use broker_only to allow brokered connections, or full_relay to also relay traffic for other peers.
  • Public endpoint — Use the "Regenerate" button above with a public IP or full tunnel endpoint so the invite contains a dialable address.
  • wss:// endpoints — wss:// means TLS-wrapped WebSocket transport. Canopy still verifies peer keys separately, and explicit wss:// endpoints are not downgraded to ws:// if TLS fails.
1 Same network (LAN)

Both on the same WiFi? Canopy discovers peers automatically — no invite needed.

2 Different location

One person shares a reachable endpoint: public IP plus port-forwarding, a VPS public IP, or a full tunnel endpoint such as wss://.... Prefer wss:// for public internet use when TLS is really terminated at that endpoint.

3 Friend imports the code

The friend pastes the invite code and clicks Connect. Canopy verifies the identity and establishes an encrypted channel.
